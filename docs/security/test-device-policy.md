# 真实设备测试策略

## 1. 作用域

- Android 平板使用逻辑标识 `TEST_TABLET`。
- TCode 实物使用逻辑标识 `TEST_OSR_DEVICE`。
- 串口、设备序列号、网络地址和凭据只通过运行时环境/本地未跟踪配置提供。
- 本策略不构成固件烧录授权。

## 2. Android 平板允许范围

只允许：

- 查询连接状态、系统/API/屏幕能力和本项目包信息；
- 安装签名为开发用途且包名严格等于本项目 `applicationId` 的 APK；
- 启动/停止本应用、读取本应用 PID 的过滤日志；
- 访问本应用私有目录；
- 在用户明确指定的中性测试媒体目录中创建/读取/清理本项目测试文件；
- 对本应用授予测试所需且用户知情的运行时权限。

即使 adbd 以 root 运行，也禁止：

- 读取/修改 `/data/data` 或 `/data/user` 下其他包；
- 修改系统设置、账户、权限数据库、SELinux、系统分区、启动项或属性；
- 遍历/复制未授权媒体目录；
- 恢复出厂、`dd`、格式化、重挂载、批量包操作或宽范围递归删除；
- 清除、停用、卸载任何非本项目包；
- 把真实媒体名、缩略图、日志或应用数据提交仓库。

## 3. ADB 操作规程

运行前在当前 shell 设置逻辑变量，不能写入仓库：

```powershell
$env:ANDROID_SERIAL = '<TEST_TABLET_SERIAL>'
$appId = 'io.github.fplayer.android'
adb -s $env:ANDROID_SERIAL get-state
adb -s $env:ANDROID_SERIAL shell pm path $appId
```

任何写操作前检查：

1. `ANDROID_SERIAL` 精确匹配目标；
2. APK manifest 的 applicationId 精确匹配 `$appId`；
3. 目标路径属于本应用私有目录或用户本次明确指定的测试目录；
4. `PROGRESS.md` 已说明当前测试目的和清理范围。

不得使用变量展开后的空路径执行删除。清理时先输出并核对解析后的绝对目标；优先由应用自身删除其缓存。`pm clear` 仅能对本项目包执行，且会删除测试状态，必须在任务验收明确需要时使用。

## 4. TCode 实物允许范围

默认只允许打开连接、读取非敏感握手/状态（若协议支持）、发送低幅短时测试命令和执行停止策略。

禁止：

- 擦除/烧录/更新 ESP32 固件；
- 写入持久 Wi-Fi、蓝牙、轴映射或机械配置；
- 使用全幅、无限时域或未限速的动作；
- 绕过 `DeviceSafetyController` 从测试 UI 直接写串口/socket；
- 同时让两个进程控制同一设备；
- 在人体连接状态下进行开发测试。

首次动作测试要求：

1. 设备机械结构空载、可目视、可立即断电；
2. 只启用一个已确认轴；
3. 使用安全中心附近的小范围和不超过 500 ms 的命令；
4. 先验证软件停止，再验证拔线/断连后的短时失效；
5. 保存脱敏的期望/实际命令摘要，不保存高频原始长期日志。

## 5. 故障和停止

- 测试失败首先停止命令生成、增加 generation、清空队列，再尝试设备停止，最后关闭 transport。
- 不能因为停止帧发送失败而继续重放普通动作。
- 发现设备行为与预期不符时立即断开物理电源并停止本轮测试，不用更大命令“试试看”。
- force-stop 不能保证执行清理，真实测试前必须已经验证短时域策略。

## 6. 凭据与日志

- SSH、SMB、蓝牙、网络和签名凭据禁止写入仓库、Gradle、命令历史示例和日志。
- 日志中的设备序列号、网络地址、用户名、媒体路径使用稳定脱敏 token。
- 需要分享诊断时先生成预览，用户明确确认后再对外发送；默认不发送任何数据。
